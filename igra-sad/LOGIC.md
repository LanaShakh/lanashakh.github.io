# «Сад камней» — формальное описание логики

Этот документ полностью описывает правила игры, формат уровней, алгоритм генерации
и проверку решаемости. По нему можно сгенерировать новые корректные уровни
без доступа к коду игры.

## 1. Правила игры

- Игровое поле — прямоугольная сетка размером до 8 столбцов × 11 строк.
- Типы клеток:
  - `.` — песок: проходимая клетка, которую **надо проборонить**;
  - `S` — песок + стартовая позиция камня игрока (ровно одна на уровне);
  - `#` — валун: непроходимое препятствие;
  - ` ` (пробел) — клетка вне сада: непроходима и не участвует в цели.
- Камень ходит свайпом в одном из 4 направлений (вверх/вниз/влево/вправо).
- **Правило скольжения**: камень движется по прямой от клетки к клетке и
  останавливается **перед** первой непроходимой клеткой. Непроходимо всё,
  что не является песком: валун `#`, клетка ` `, выход за границы сетки.
- Все клетки, пройденные камнем за ход, **включая начальную и конечную**,
  становятся «проборонёнными». Для каждой клетки запоминается направление
  хода, которым её проборонили (для отрисовки борозд вдоль движения).
  Повторное прохождение по клетке разрешено и просто перезаписывает направление.
- Ход, в котором камень не может сдвинуться ни на одну клетку
  (упирается сразу), **не считается ходом** и никак не учитывается.
- **Победа**: проборонены все песчаные клетки (`.` и `S`).
- Таймеров и ограничений на число ходов нет. Доступны полный откат ходов
  (undo-стек) и рестарт уровня.

## 2. Звёзды

У каждого уровня есть `par` — **минимально возможное** число ходов
(вычисляется решателем, см. раздел 5, никогда не задаётся вручную):

| Ходов затрачено | Звёзды |
|---|---|
| ≤ par | ★★★ |
| ≤ par + 2 | ★★ |
| больше | ★ |

## 3. Формат уровня

Уровень — объект:

```js
{ name: 'Название', par: 7, map: [
  ".#    ",
  "S     ",
  ".     ",
  "......",
] }
```

Требования к `map`:
- массив строк одинаковой длины; ширина ≤ 8, высота ≤ 11;
- допустимые символы: `.` `#` ` ` `S`;
- ровно один `S`;
- число песчаных клеток (`.` + `S`): от 12 до 35;
- крайние строки и столбцы не должны быть целиком пробельными (карта обрезана);
- уровень обязан быть решаемым, `par` = минимум ходов по решателю, `par ≥ 5`.

Направления кодируются буквами `U R D L` (вверх, вправо, вниз, влево);
решение уровня — строка из этих букв.

## 4. Алгоритм генерации уровня

Метод «обратной прогулки»: уровень строится из честной случайной партии,
поэтому он решаем по построению.

1. **Заготовка**: выбрать размеры `w ∈ [6..8]`, `h ∈ [8..11]`. Граница сетки
   непроходима (выход за пределы = стена). Случайно расставить валуны
   на 10–18 % клеток.
2. **Старт**: случайная клетка без валуна.
3. **Прогулка** (8–30 шагов): на каждом шаге:
   - для всех 4 направлений просчитать скольжение по правилу игры
     (препятствия на этом этапе — только валуны и граница сетки);
   - оставить направления, в которых камень реально сдвигается;
   - если есть альтернативы, исключить направление, противоположное
     предыдущему ходу (избегаем немедленного «туда-обратно»);
   - следить, чтобы суммарное число посещённых клеток не превысило 35
     (лимит решателя); ходы, нарушающие лимит, отбрасывать;
   - выбрать случайное направление из оставшихся, передвинуть камень,
     пометить все клетки пути посещёнными; если остановка произошла
     о валун — запомнить этот валун как «стопор».
4. **Карта**: посещённые клетки → `.`, стартовая → `S`;
   валуны-стопоры → `#` (обязательно!); прочие валуны, соседствующие
   с песком (8-соседство), можно оставить `#` как декорацию;
   все остальные клетки → ` `. Обрезать пустые крайние строки/столбцы.

   Замечание о корректности: превращение непосещённых клеток в ` ` не ломает
   решение-прогулку, т.к. все клетки каждого отрезка пути стали песком,
   а клетка-останов после отрезка — либо сохранённый валун, либо граница/` `
   (оба непроходимы), т.е. прогулка воспроизводится в игре ход в ход.

## 5. Решатель (проверка и вычисление par)

Поиск в ширину (BFS) по состояниям — гарантированно находит минимум ходов.

- Пронумеровать песчаные клетки `0..n-1` (n ≤ 35).
- **Состояние**: `(позиция камня, битовая маска проборонённых клеток)`.
  Маску хранить как пару 32-битных чисел (биты 0–19 и 20–34) или BigInt.
- Предвычислить для каждой песчаной клетки и каждого направления:
  клетку-назначение и маску бит всех клеток пути (включая начальную);
  переходы, где камень не двигается, отбросить.
- BFS из состояния `(S, пустая маска)`; посещённые состояния — в
  хеш-таблице (мемоизация), повторные состояния не раскрывать.
- Целевое состояние: маска = все n бит. Глубина достижения = `par`;
  цепочка предков даёт строку-решение.
- Отсечение: если раскрыто > ~600 000 состояний — кандидата отбросить.

## 6. Фильтр вырожденных уровней

Отбрасываются кандидаты, у которых:
- `par < 5` (в т.ч. решение одной прямой, par = 1);
- песчаных клеток < 12 или > 35;
- решатель не нашёл решение в лимит состояний;
- карта совпадает с уже принятой (дедупликация по строкам карты).

## 7. Подбор набора уровней

Сгенерировать большой пул кандидатов (тысячи сидов), отсортировать по
сложности — первично по `par`, вторично по числу песчаных клеток и площади —
и выбрать 14 уровней с монотонно неубывающим `par`, равномерно покрывающих
диапазон сложности (в текущей сборке par: 5, 6, 7, 8, 9, 10, 11, 13, 14, 15,
16, 17, 18, 19). Первые уровни — маленькие карты с малым количеством песка,
последние — крупные.

## 8. Прочее (интеграция)

- Прогресс: `localStorage['sad_stars']` — JSON-массив лучших звёзд по уровням;
  уровень `i` открыт, если `i === 0` или у уровня `i-1` есть звёзды.
- Звук: `localStorage['sad_snd']` (`'0'` = выкл).
- Для автотестов игра экспонирует `window.__move(d)`, где `d ∈ {'U','R','D','L'}` —
  мгновенный ход без анимации; возвращает `true`, если камень сдвинулся.
