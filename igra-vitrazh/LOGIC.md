# Витраж — формальная логика игры

Документ для человека или LLM (Claude Opus и др.), которым нужно генерировать
новые уровни или расширять игру, не читая весь код.

## Модель мира
- Поле — сетка `GRID_W×GRID_H` = 9×12. Координаты `x∈[0..8]`, `y∈[0..11]`, ось y вниз.
- Направления: `0 →`, `1 ↓`, `2 ←`, `3 ↑`. Шаг: `DX=[1,0,-1,0]`, `DY=[0,1,0,-1]`.
- В клетке не более одного предмета.

## Предметы
| Код  | Предмет | Поведение луча |
|------|---------|----------------|
| `em` | излучатель `[x,y,dir,color]` | испускает луч цвета `color` в `dir`; сам непрозрачен |
| `mr` | поворотное зеркало `[x,y,solO,initO]` | отражает; тап игрока переключает `o ^= 1` |
| `mf` | закреплённое зеркало `[x,y,o]` | отражает, не вращается |
| `sp` | расщепитель `[x,y]` | поглощает луч, испускает два: `(d+1)%4` и `(d+3)%4` (прямо луч НЕ проходит) |
| `fl` | стекло-фильтр `[x,y,color]` | луч проходит насквозь в том же направлении, но его цвет становится `color` |
| `tg` | роза-мишень `[x,y,color]` | поглощает луч; «зажжена», если получила луч ровно своего цвета |
| `wl` | камень `[x,y]` | поглощает луч |

Ориентация зеркала: `o=0` это `/`, `o=1` это `\`.
Таблица отражений `REFL[o][d] → d'`:
- `/`: `[3,2,1,0]` (→↑, ↓←, ←↓, ↑→)
- `\`: `[1,0,3,2]` (→↓, ↓→, ←↑, ↑←)

Цвета: `w` белый, `g` золотой, `r` рубиновый, `b` сапфировый, `e` изумрудный.
Смешения нет: мишень зажигается только точным цветом (белый ≠ любой).

## Трассировка (детерминированная)
BFS/DFS по лучам от всех излучателей. Луч = `(x, y, d, c)`, где `(x,y)` —
клетка испускания. Луч идёт по клеткам до первого предмета/границы.
Зацикливание исключается множеством посещённых состояний `(x,y,d,c)` и
общим лимитом ~400 лучей.

## Победа и звёзды
- Победа: каждая `tg` зажжена своим цветом одновременно.
- `par` уровня = число `mr`, у которых `initO ≠ solO` (расстояние Хэмминга
  до решения). Звёзды: поворотов ≤ par+1 → ★★★, ≤ par+4 → ★★, иначе ★.

## Формат уровня
```js
{name:'Имя', par:N, items:[
  ['em',x,y,dir,c], ['mr',x,y,solO,initO], ['mf',x,y,o],
  ['sp',x,y], ['fl',x,y,c], ['tg',x,y,c], ['wl',x,y]]}
```

## Как сгенерировать корректный уровень (обязательный рецепт)
1. Построй РЕШЁННУЮ конфигурацию: расставь излучатели, зеркала в
   ПРАВИЛЬНОЙ ориентации (`solO`), фильтры, расщепители, мишени, камни.
2. Прогони трассировку и убедись, что все мишени зажжены (это и есть
   проверка решаемости — решение существует по построению).
3. Задай `initO`: инвертируй ориентацию у K зеркал (K = par ≥ 1).
4. Прогони трассировку начального состояния и убедись, что уровень
   НЕ решён на старте.
5. Декоративные/обманные поворотные зеркала не должны стоять на пути
   решения (любая их ориентация отражает луч — «выключить» зеркало нельзя).
   У обманок ставь `initO = solO`, чтобы par оставался честным.
6. Камни и фиксированные зеркала — вне пути решения либо осознанно
   формируют его.

В игре есть тестовые хуки: `window.__startLevel(i)`,
`window.__applySolution()` (поворачивает все `mr` в `solO`, возвращает
победу), `window.__isWin()`. Автотест обязан прогонять их для каждого
нового уровня.

## Идеи расширения (совместимы с моделью)
- Смешение цветов (две компоненты на мишени), полупрозрачные зеркала
  (отражают + пропускают), призма (раскладывает белый на 3 цветных луча
  в стороны), поворот зеркал на 45° с 4 состояниями, переносимые зеркала.
