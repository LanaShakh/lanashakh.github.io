# «Часовщик» — формальное описание правил и формата уровней

Документ самодостаточен: по нему можно сгенерировать новые уровни, не заглядывая в код игры.
Вся геометрия и логика ниже — ровно те, что зашиты в `index.html` (константы и функции совпадают дословно).

## 1. Система координат

- Все координаты — **в долях ширины доски**: `x ∈ [0..1]`.
- Доска (поле) портретная: `y ∈ [0 .. 4/3]` (высота поля = 4/3 ширины). Ниже поля — лоток со свободными шестернями (в геометрии уровня не участвует).
- Ось `y` направлена **вниз** (экранные координаты). Положительная угловая скорость = вращение **по часовой стрелке** на экране.

## 2. Шестерни

| Размер | Радиус делительной окружности `r` | Зубьев (визуально) |
|--------|-----------------------------------|--------------------|
| `S`    | 0.055                             | 10                 |
| `M`    | 0.075                             | 14                 |
| `L`    | 0.100                             | 18                 |

Константы:

```js
const SIZES    = { S: 0.055, M: 0.075, L: 0.100 };
const MESH_TOL = 0.014;                 // допуск сцепления
const DRIVER_W = 0.4 * 2 * Math.PI;    // заводная: 0.4 об/с, знак «+» = по часовой
```

Типы шестерён:
- **Заводная** (`driver`) — закреплена на своём штырьке, всегда крутится сама с угловой скоростью `+DRIVER_W` (по часовой). Снять нельзя.
- **Целевая** (`target`) — закреплена, несёт часовую стрелку и индикатор требуемого направления. Снять нельзя.
- **Свободные** — лежат в лотке; игрок тапом ставит их на пустые штырьки и снимает обратно.

## 3. Математика сцепления

Две шестерни с центрами `p1`, `p2` и радиусами `r1`, `r2` **сцеплены** тогда и только тогда:

```
| dist(p1, p2) − (r1 + r2) | < 0.014        (MESH_TOL)
```

- `dist > r1 + r2 + 0.014` — шестерня «не дотягивается»: стоит и не крутится.
- `dist < r1 + r2 − 0.014` — **перекрытие**: игра запрещает такую установку (шестерня не ставится, красная вспышка у штырька).

## 4. Передача вращения (BFS)

От заводной шестерни запускается BFS по графу сцеплений:

- при переходе `i → j`: `w_j = − w_i · r_i / r_j` (направление меняется на противоположное, скорость — по передаточному отношению);
- если BFS приходит к уже посещённой шестерне и **знак** нового значения не совпадает с уже присвоенным — механизм **клинит**: все шестерни компоненты останавливаются и мелко дрожат, показывается надпись «Клинит!». Совпадающий знак — допустимо (модуль скорости вдоль любого пути одинаков: `|w_j| = DRIVER_W · r_заводной / r_j`, телескопирование отношений);
- шестерни вне компоненты заводной имеют `w = 0` (стоят).

Эталонная реализация (дословно из игры и из скрипта проверки):

```js
function buildGears(level, placement) {
  const gs = [];
  const add = (peg, size, kind) => gs.push({ x: level.pegs[peg].x, y: level.pegs[peg].y, r: SIZES[size], size, peg, kind });
  add(level.driver.peg, level.driver.size, 'driver');
  add(level.target.peg, level.target.size, 'target');
  for (const k in placement) add(+k, placement[k], 'placed');
  return gs;
}
function solveMech(gears) {
  const n = gears.length, adj = Array.from({ length: n }, () => []);
  for (let i = 0; i < n; i++) for (let j = i + 1; j < n; j++) {
    const d = Math.hypot(gears[i].x - gears[j].x, gears[i].y - gears[j].y);
    if (Math.abs(d - (gears[i].r + gears[j].r)) < MESH_TOL) { adj[i].push(j); adj[j].push(i); }
  }
  const w = new Array(n).fill(0), seen = new Array(n).fill(false);
  const di = gears.findIndex(g => g.kind === 'driver');
  w[di] = DRIVER_W; seen[di] = true;
  let jam = false; const q = [di];
  while (q.length) {
    const i = q.shift();
    for (const j of adj[i]) {
      const cand = -w[i] * gears[i].r / gears[j].r;
      if (!seen[j]) { seen[j] = true; w[j] = cand; q.push(j); }
      else if (Math.sign(cand) !== Math.sign(w[j])) jam = true;
    }
  }
  return { w, jam, seen, adj };
}
function checkWin(level, placement) {
  const gs = buildGears(level, placement);
  const { w, jam } = solveMech(gs);
  const ti = gs.findIndex(g => g.kind === 'target');
  return !jam && w[ti] !== 0 && Math.sign(w[ti]) === level.dir;
}
```

## 5. Победа и звёзды

- **Победа**: `checkWin` истинен — целевая крутится, направление совпадает с требуемым (`level.dir`), клина нет. Проверяется после каждого изменения; засчитывается с задержкой 0.8 с (игрок видит, как всё закрутилось).
- **Направление**: `dir = +1` — по часовой (⟳), `dir = −1` — против (⟲). Чётность: при `k` сцеплениях на пути от заводной к целевой знак цели = `(+1)·(−1)^k`.
- **Звёзды**: использовано шестерён `= par` → ★★★, `= par + 1` → ★★, иначе ★.

## 6. Формат уровня

```js
{
  "name": "Цепочка",          // название по-русски
  "dir": -1,                   // требуемое направление целевой: +1 ⟳ / -1 ⟲
  "par": 2,                    // число шестерён в эталонном решении
  "pegs": [ {"x":0.3,"y":0.62}, ... ],   // все штырьки (оси); индексация с 0
  "driver": { "peg": 0, "size": "M" },   // заводная: штырёк + размер
  "target": { "peg": 1, "size": "M" },   // целевая: штырёк + размер
  "tray":   ["S","S","M"],               // лоток: точный мультинабор свободных шестерён
  "solution": { "2": "S", "3": "S" },    // эталон: индекс штырька -> размер (для проверки и __solve)
  "hint": "..."                          // (опц.) подсказка, показывается 1 раз
}
```

Соглашения: штырёк 0 — заводная, штырёк 1 — целевая, дальше — штырьки решения, в конце — обманки.

## 7. Рецепт проектирования уровня (обязательный порядок)

1. **Сначала придумай решение**: цепочку (или ветвление) размеров от заводной к целевой, например `M → S → S → M`.
2. **Рассчитай позиции из решения**: каждый следующий центр — на расстоянии **ровно `r1 + r2`** (допустимо ±0.004) от предыдущего, под выбранным углом:
   `next = prev + (r1+r2) · (cos θ, sin θ)`.
   Суммы радиусов: S+S = 0.110, S+M = 0.130, S+L = 0.155, M+M = 0.150, M+L = 0.175, L+L = 0.200.
   Если ветка должна замкнуться на уже стоящую шестерню — последний центр ищи пересечением двух окружностей.
3. **Проверь все НЕсоседние пары** конфигурации решения: расстояние обязано быть `> r1 + r2 + 0.019` (чистая «серая зона» запрещена — случайное сцепление или почти-сцепление недопустимо). Соседние: `|d − (r1+r2)| < 0.011`.
4. **Габариты**: центры шестерён `x ± r ∈ [0.02 .. 0.98]`, `y − r > 0.155` (сверху HUD), `y + r < 4/3 − 0.03`. Штырьки: `x ∈ [0.05..0.95]`, `y ∈ [0.19 .. 4/3−0.05]`.
5. **Добавь 1–3 штырька-обманки** в стороне: расстояние от обманки до **каждой** шестерни конфигурации решения и до других обманок `> 0.214` (= L+L+допуск: тогда любая шестерня на обманке гарантированно ни с чем не взаимодействует).
   Исключение — «путевые» штырьки-ловушки (альтернативный путь с неверной чётностью или ветка, дающая клин): они сознательно близко, их эффект надо проверить отдельно (см. п. 8).
6. **Лоток** = точный набор решения + 0–2 лишние шестерни. Лишние не должны открывать более короткое решение (обычно гарантируется пп. 3 и 5: не та сумма радиусов либо изоляция обманок).
7. `dir` = фактический знак целевой в решении: `+1` при чётном числе сцеплений на пути, `−1` при нечётном. `par` = числу шестерён решения.

## 8. Обязательная проверка

Каждый новый уровень прогоняется скриптом с функциями из п. 4 (в репозитории игры это `check-chasy.js`, он читает `LEVELS` прямо из `index.html`):

- `checkWin(level, level.solution) === true` — решение выигрывает;
- каждая пара шестерён решения либо чисто сцеплена, либо чисто врозь (п. 7.3);
- лоток покрывает решение; `par` совпадает;
- для ловушек — целевые ассерты (пример: у «Развилки» ветка `M` одна даёт `Math.sign(w[target]) ≠ dir`, обе ветки вместе — `jam === true`).

## 9. Управление (для полноты картины)

Только тапы, без перетаскивания: тап по шестерне в лотке — выбрать; тап по пустому штырьку — поставить выбранную (если нет перекрытия, п. 3); тап по своей шестерне на доске — вернуть в лоток. Заводную и целевую снять нельзя. Таймеров нет.
